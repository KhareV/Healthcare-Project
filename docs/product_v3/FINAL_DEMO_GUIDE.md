# V3 guided demonstration

1. Start the V3 API and SvelteKit app using the [runbook](../../RUNBOOK.md#current-v3-product). Check `/health` and `/model-metadata` for the V3 release before presenting a forecast.
2. Open `/demo`. The [additive showcase manifest](../../configs/performance_v3_product/showcase_manifest_v1.json) contains eight development-only cases and 79 total legal replay cutoffs: improvement (5), deterioration (10), heart failure (11), ischemic (12), arrhythmia (12), new organ-support initiation (12), sparse observations (5), and a long episode (12). Their titles and event notes come from observed structured data, not from model-error selection. No final-test stay is present.
3. Select a scenario and step, play, pause or drag through legal cutoffs. Each cutoff recomputes V3 output using history available up to that time. Observed events revealed later in replay must be understood as hindsight, not earlier model inputs. Compare two different scenarios side by side to discuss trajectories; these selected examples are not an unbiased evaluation sample.
4. Open `/patients` for the same case to inspect the eight-bin history, current SOFA, independent +24h/+48h forecasts, remaining ICU time, calibrated support risk and task-specific TreeSHAP. The support attribution explains raw model output before Platt calibration.
5. Open `/cohort` for development-cohort composition, observation availability and eligibility. Open `/research/analytics` and its linked workbench pages for saved final metrics, model comparisons, calibration, errors, ablations and robustness. Show `/research/defect` for historical V2 defect D1 and the separate V3.1 privileged diagnostic.
6. Open `/reports` to download available evidence exports. The registry and per-file sidecars bind chart and table data to exact source artifacts and hashes. A downloaded figure is not a new scientific evaluation.
7. With a dedicated test account and MongoDB configured, enter a custom encounter, request a forecast, upload a synthetic PDF report, analyze candidates, then confirm selected values at an encounter hour. Recompute a cutoff after the event and inspect prediction history for bundle and data-revision labels. Report extraction and Copilot commentary require Groq; the numerical forecast does not.

Use synthetic/demo records only. Do not present the platform as real-time clinical decision support.
