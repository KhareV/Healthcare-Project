## Governance and reproducibility

Candidate manifests were generated by deterministic Latin hypercube sampling and hashed before training. All runs used the exact Phase-10 transformed train/validation rows, observation masks, TSLO, padding, statics, split, feature schema, and target contracts. Checkpoints bind G1, Phase 14, split, preprocessing, feature schema, config, seed, and committed code.

Each winner was retrained once as a non-budget audit attempt. All validation prediction artifacts reproduced byte-for-byte and all compared metrics had zero absolute difference at tolerance `1e-8`.

An initial v1 transaction wrote one valid recovery candidate before artifact indexing rejected a missing prediction-population hash. That search version was marked failed and preserved for audit. The defect was fixed and committed, retry scoping was corrected to include search version, and the complete 90-config search restarted as v2 from candidate 001. No v1 result participates in v2 ranking.
